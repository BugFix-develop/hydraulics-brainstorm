## 2. Пользовательские типы данных (C++)

### 2.1. Структура исходных данных (`*_properties_t`)
Хранит неизменяемые физические и топологические параметры:

```cpp
struct [task_name]_properties_t {
    basic_graph_t graph;                     ///< Ориентированный граф цепи
    std::vector<double> branch_resistances;   ///< Коэффициенты сопротивления дуг r_i [Па/(м3/с)]
    std::vector<double> branch_active_heads;  ///< Активные напоры дуг H_i [Па]
    std::vector<double> nodal_inflows;        ///< Узловые отборы/притоки Q_j на Q-узлах [м3/с]
    std::vector<double> boundary_pressures;   ///< Фиксированные давления P_{p, k} на P-узлах [Па]
};
```
*Контракт:* Все векторы должны иметь положительные размеры, согласованные с размерностями графа ($n$, $m_Q$, $m_P$).

### 2.2. Структура результатов расчета (`*_result_t`)
```cpp
struct [task_name]_result_t {
    std::vector<double> branch_flow_rates;    ///< Рассчитанные расходы в ветвях x [м3/с]
    std::vector<double> nodal_pressures;      ///< Рассчитанные давления в Q-узлах P [Па]
    double max_equation_residual;             ///< Максимальная невязка СЛАУ ||A*z - b||_inf
    double max_kirchhoff_residual;            ///< Максимальная невязка узловых балансов ||A*x - Q||_inf
    bool is_converged{false};                 ///< Флаг успешной сходимости решения
};
```

## 3. Интерфейс и контракты классов

### 3.1. Класс солвера (`*_solver_t`)
Класс не владеет изменяемым состоянием и выполняет строго расчетную функцию:

```cpp
class [task_name]_solver_t {
public:
    /**
     * @brief Конструктор солвера с валидацией входных параметров
     * @param properties Неизменяемая структура параметров задачи
     * @throw std::invalid_argument при несогласованности размерностей векторов
     */
    explicit [task_name]_solver_t(const [task_name]_properties_t& properties);

    /**
     * @brief Выполнить расчет потокораспределения
     * @return Структура с рассчитанными векторами расходов и давлений
     * @throw std::runtime_error при вырожденности ранга матрицы СЛАУ
     */
    [task_name]_result_t solve() const;

private:
    const [task_name]_properties_t& properties_;

    /// @brief Сборка блочной матрицы СЛАУ A_block и вектора правой части b_vec
    void assemble_system(Eigen::MatrixXd& A_block, Eigen::VectorXd& b_vec) const;

    /// @brief Проверка численного ранга через Eigen::FullPivLU
    std::size_t compute_matrix_rank(const Eigen::MatrixXd& matrix) const;
};
```

## 4. Принципы проектирования и обоснование решений

1. **Владение vs Расчет:**
   * Данными владеет вызывающий код или класс-таск;
   * Солвер принимает ссылку на неизменяемые `properties_t` и не хранит промежуточные состояния между вызовами `solve()`.
2. **Pass only what you need:**
   * В методы расчета передаются только минимально необходимые данные, без паразитных зависимостей от сторонних модулей.
3. **Запрет на небезопасные операции Eigen:**
   * Категорически запрещено использование `matrix.inverse() * b`;
   * Решение СЛАУ выполняется исключительно через `Eigen::PartialPivLU::solve()`;
   * Анализ ранга выполняется через `Eigen::FullPivLU::rank()`.

## 5. Поведение на ошибках и граничных случаях

| Ситуация / Ошибка | Реакция кода | Обоснование |
|---|---|---|
| Несогласованность размерностей графа и векторов | Выброс `std::invalid_argument` | Нарушение предусловия контракта до начала вычислений |
| Неположительное гидравлическое сопротивление ($r_i \le 0$) | Выброс `std::invalid_argument` | Нарушение физического инварианта пассивной дуги |
| Отсутствие опорных $P$-узлов ($m_P = 0$) | Выброс `std::invalid_argument` | Гидростатическая незакрепленность цепи |
| Вырожденность матрицы СЛАУ ($\operatorname{rank} < N$) | Выброс `std::runtime_error` | Система не имеет единственного решения |
| Невязка решения превышает допуск ($\varepsilon > 10^{-8}$) | Поле `is_converged = false` | Сигнализация о потере численной точности |
